# Школьное портфолио — инструкция по запуску

Простой сайт на чистом HTML/CSS/JS + Supabase (Auth, Postgres, Storage) + Vercel.

## Структура проекта

```
index.html          — вход
register.html        — регистрация
dashboard.html        — личный кабинет ученика (портфолио + мои события)
portfolio.html         — публичная страница портфолио (?id=USER_ID)
calendar.html          — календарь событий
teacher.html           — панель учителя
admin.html             — панель админа
css/style.css
js/supabaseClient.js   — сюда вписываете URL и ключ Supabase
js/common.js            — общие функции (сессия, шапка сайта)
js/dashboard.js, calendar.js, teacher.js, admin.js
sql/schema.sql          — таблицы + RLS-политики, выполнить в Supabase
robots.txt, vercel.json
```

## Шаг 1. Создать проект в Supabase

1. Зайдите на supabase.com → New project (бесплатный тариф).
2. Дождитесь создания проекта.
3. Откройте **SQL Editor** → вставьте туда содержимое файла `sql/schema.sql` целиком → **Run**.
   Это создаст все таблицы, триггеры и RLS-политики, а также публичный Storage-бакет `portfolio-files`.
4. Откройте **Project Settings → API** и скопируйте:
   - `Project URL`
   - `anon public` ключ

## Шаг 2. Подключить ключи в коде

Откройте `js/supabaseClient.js` и замените:

```js
const SUPABASE_URL = 'https://ВАШ-ПРОЕКТ.supabase.co';
const SUPABASE_ANON_KEY = 'ВАШ-ANON-KEY';
```

на реальные значения из шага 1. Анонимный ключ безопасно хранить в клиентском коде — доступ разграничивается через RLS-политики в базе, а не через секретность ключа.

По умолчанию Supabase требует подтверждение email при регистрации. Если хотите, чтобы ученики входили сразу после регистрации без подтверждения почты — отключите это в **Authentication → Providers → Email → "Confirm email"**.

## Шаг 3. Залить код на GitHub

```bash
cd school-portfolio
git init
git add .
git commit -m "Первая версия школьного портфолио"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/ВАШ-РЕПОЗИТОРИЙ.git
git push -u origin main
```

(Репозиторий на GitHub нужно создать заранее — пустой, без README, через github.com → New repository.)

## Шаг 4. Задеплоить на Vercel

1. Зайдите на vercel.com → **Add New → Project**.
2. Выберите только что созданный GitHub-репозиторий.
3. Framework Preset — **Other** (это статический сайт, сборка не нужна).
4. Root Directory — оставить как есть (корень репозитория).
5. Нажмите **Deploy**.

После деплоя Vercel даст ссылку вида `https://ваш-проект.vercel.app` — это и есть рабочий сайт.

Дальше при каждом `git push` в ветку `main` Vercel будет автоматически передеплоивать сайт.

## Шаг 5. Назначить себя админом

Пока в базе нет ни одного админа — назначить роль может только сам админ. Поэтому первого админа нужно назначить вручную:

1. Зарегистрируйтесь на сайте как обычный ученик (своим email).
2. В Supabase → **SQL Editor** выполните (подставив свой email):
   ```sql
   update public.profiles set role = 'admin' where email = 'ваш-email@example.com';
   ```
3. Перезайдите на сайте — появится вкладка «Админ», через которую дальше можно назначать учителей.

## Что уже сделано по безопасности и приватности

- Row Level Security включён на всех таблицах: ученик может редактировать только свои элементы портфолио, создавать события может только teacher/admin, менять роль может только admin (это дополнительно форсируется триггером на таблице `profiles`, а не только политикой).
- `robots.txt` запрещает индексацию всего сайта, плюс на каждой странице стоит `<meta name="robots" content="noindex, nofollow">` и заголовок `X-Robots-Tag` в `vercel.json`.
- При регистрации собираются только имя, фамилия, класс и email — без лишних персональных данных.
- Файлы портфолио загружаются в приватную по структуре папку `<user_id>/...` в Storage; загружать/удалять может только сам владелец, но публичная ссылка на файл открыта на чтение (нужно для публичной страницы портфолио).

## Что можно добавить позже (не сделано в этой версии)

- Восстановление пароля (Supabase это умеет из коробки через `resetPasswordForEmail`, но UI под это не сделан).
- Уведомления на email о новых событиях.
- Экспорт портфолио в PDF.
- Красивые "человеческие" ссылки на портфолио (`/portfolio/ivan-petrov` вместо `?id=uuid`) — потребует отдельную таблицу slug → user_id.
